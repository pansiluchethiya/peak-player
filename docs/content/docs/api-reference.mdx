The Peak API is JSON over HTTP, with two exceptions: the media proxy streams bytes with `Range`
support, and the stream events endpoint emits `text/event-stream`.

## Base URL

```text
http://localhost:3000
```

Set the base URL to your deployment origin in production. The player uses the same API through the
`NEXT_PUBLIC_API_BASE`/server configuration of your deployment.

## Authentication

Only `POST /api/v1/embed/sessions` requires a partner key:

```http
x-api-key: YOUR_PARTNER_KEY
```

All other public endpoints are unauthenticated by design, but media access is still protected by
signed proxy URLs and embed tokens. Admin IPTV endpoints use the platform’s admin session
authentication and are not part of the partner contract.

## Conventions

- Success responses include `success: true` where the endpoint returns an envelope.
- Errors include `{ success: false, error, message }` for partner-facing endpoints.
- Media ids are strings in JSON, even when they are numeric TMDB ids.
- Timestamps are ISO-8601 strings in responses.
- Unknown fields are ignored; invalid required fields are rejected.

## Rate limits

The media proxy applies rate limiting per client and per signed URL. A `429` response includes a
retry hint. Do not retry aggressively; back off and let the player fail over to another source.

## CORS

The API is intended to be called from trusted server-side code. The player and proxy use restricted
CORS. Do not assume a browser can call session creation directly with a partner key.
